BROAD OVERIEW
Step 1: Symbolic Abstraction
Robot looks at block positions and figures out relationships
"red block is on blue block" "green block is on table" "yellow is clear"

Step 2: Task Planning
Organizing what needs to happen first
"pick up blue block, then red"

Step 3: Motion Primitives
How to actually pick up blocks
"robot actually picks up a block"

Step 4: Execution Loop
Checks if it worked and if it worked move on and if it didn't try again


WHAT EACH FILE DOES
Step 1: Symbolic Abstraction "What do I see?"
    abstraction.py
    Job: Looks at where blocks are in 3D space (x, y, z coordinates) and translates to simple facts:
    Input: Block R at position (0.5, 0.0, 0.02), Block G at (0.5, 0.0, 0.06)
    Output: "R is on G", "G is on table", "R is clear"

Step 2: Task Planning "What should I do?"
    Files: task_planner.py + goals.py + blocksworld_domain.pddl
    
    goals.py
    Job: Defines the target towers you want
    Example: "I want red-green-blue tower"

    blocksworld_domain.pddl
    Job: The "rules of the game" - what actions are allowed
    Rules: "You can only pick up a block if your hand is empty AND nothing is on top of it"

    task_planner.py
    Job: Reads current state + goal + rules → makes a to-do list
    Example:
        Current: All blocks on table
        Goal: Red on green on blue
        Plan: pick-up blue → put-down blue → pick-up green → stack green on blue → pick-up red → stack red on green

Step 3: Motion Primitives "How do I move?"
    planning.py 
    Job: Takes high-level commands like "pick-up red" and turns them into actual robot arm movements:
    Input: "pick-up red block"
    Output: Joint angles, gripper commands, collision-free path

Step 4: Execution Loop "Do it and check"
    File: tamp_main.py
    Job: The conductor of the orchestra - calls everyone in order

HOW WE GET THE JOB DONE (ex: Goal 1)
1. goals.py is saying the relationships each block should have, which on are ontop of another, which are on the table, etc.
2. tamp_main.py grabs that value in goals.py creates current_problem.pddl that define each block even further. Differientating how each block starts and how it ends.
3. tamp_main.py then sends current_problem.pddl to task_planner.py
4. task_planner.py runs pyperplan, which basically creates a list of tasks that break down how to get each block to its desired position
    ex: (pick-up m) then (stack m c) then (pick-up y) then (stack y m) then (pick-up g) then (stack g b) then (pick-up r) then (stack r g)
5. task_planner.py returns plan to tamp_main.py
6. tamp_main.py tries to do run each step (primative)
